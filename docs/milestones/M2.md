# M2 — Lineage, Approval Gates, CLI Workflow

## Governing principle

Playwright produces evidence. Deterministic software normalizes and measures evidence. DeepSeek interprets and prioritizes evidence. Humans authorize consequential transitions.

## Status

**IMPLEMENTED** (2026-09-11). Verified by `tests/e2e/m2-gates.test.ts` (19 tests),
`packages/approvals/src/approvals.spec.ts` (28), `packages/lineage/src/lineage.spec.ts` (11),
and `tests/docs/approval-authority.spec.ts` (M2-AT-13).

## Entry criteria

- **M1 Reliability Gate passes.** Met: the gate passes twice sequentially with zero retries and
  zero infrastructure failures. Execution on a GitLab runner remains an external verification
  blocker (no runner is registered), which `docs/m0-decisions.md` decision 5 records.
- Explicit authorization from the user. Met: M0 through M8 authorized on 2026-09-11.

## Scope

1. `packages/lineage`: node/edge model, append-only records, per-investigation monotonic `seq`, hash chain, ancestor/descendant closure queries.
2. `packages/approvals`: the three-gate state machine, proposal canonicalisation and checksums, approval file parsing and validation (all nine checks), allowed edit surface per gate, effective-proposal computation and storage, `ApprovalRecord` insertion.
3. Proposal rendering: canonical JSON + `.sha256` + human-readable markdown, generated deterministically from the JSON.
4. Gate enforcement wired into the CLI: `run` requires gate 1, `frequency run`/`minimize`/`revalidate` require gate 2, `report`/`export` require gate 3.
5. `investigate intake --from <file>` storing the raw report as an artifact and assigning `INV-nnn` (no AI; the `Flow` is supplied as a file in M2 and produced by AI in M3).
6. `investigate approve <gate> --from <file> --checksum <sha256>` and `--scaffold`.
7. `investigate suite generate` (deterministic Playwright suite emission from an approved experiment).
8. Auxiliary read commands: `investigate status`, `investigate show`, `investigate lineage`, `investigate retention apply`.
9. Removal of the M1 `--fixture-experiment` bypass flag.
10. Destructive-action classifier and the acknowledgement requirement enforced at approval and at enqueue.

## Out of scope

AI flows and any DeepSeek call (M3). `classify`, `minimize`, `report` command bodies beyond gate wiring. Frequency statistics (M5). The `direct_evidence_attestation` approval type (deliberately absent; see open question Q10).

## Interfaces touched

`MetadataStore` (lineage, approvals tables), `ArtifactStore` (proposal and effective-proposal artifacts), `WorkQueue` (enqueue now requires an approval), CLI contract (approval commands, exit codes 2 and 3).

## Exit criteria

1. No execution path can enqueue or run a job without a valid `ApprovalRecord` for gate 1. Asserted by negative tests over every entry point, including the removed bypass flag.
2. All nine approval validation checks are implemented and each has a failing-case test.
3. A checksum mismatch between the flag, the file, and the on-disk artifact each independently yields exit 3.
4. An edit outside the gate's allowed surface, or an edit whose `from` does not match the current value, is rejected.
5. Every destructive action in an approved item requires an acknowledgement with justification; absence blocks approval and blocks enqueue.
6. Lineage records exist for every stage transition performed in M2, each carrying `actor.kind`, and the hash chain verifies via `investigate doctor --verify-lineage`.
7. `investigate lineage <id>` reconstructs the full ancestor and descendant closure offline with no browser and no provider.
8. Gate ordering is enforced: gate 2 unavailable before gate 1 approved; gate 3 before gate 2.
9. A re-rendered proposal supersedes the prior `AWAITING_APPROVAL` state without mutating any existing record.
10. `investigate suite generate` output runs standalone under the Playwright runner and reproduces the approved sequence.
11. Every M1 gate still passes.

## Demo command

```bash
investigate init --workspace ./demo-ws
investigate intake --workspace ./demo-ws --from docs/examples/intake/blank-results.md --env fixture-search
# supply a hand-written flow + experiment proposal file (AI arrives in M3)
investigate plan --workspace ./demo-ws --from docs/examples/proposals/gate-1.input.json
investigate approve experiment_selection --workspace ./demo-ws --scaffold
# edit the scaffold, then:
investigate approve experiment_selection --workspace ./demo-ws \
  --from ./demo-ws/investigations/INV-001/approvals/gate-1.approval.yaml \
  --checksum <printed sha256>
investigate run --workspace ./demo-ws --repeat 20
investigate lineage --workspace ./demo-ws RUN-001
investigate doctor --workspace ./demo-ws --verify-lineage
```

Expected: `run` refuses before approval; succeeds after; lineage prints the full chain with actors.

## Deviations from this specification, and why

| Spec item | What was built | Why |
| --- | --- | --- |
| Item 5: `intake` assigns `INV-nnn` and stores the raw report | As specified, plus the report passes through the redaction boundary under a new `report.body` scope | A human's bug report routinely contains a session id or a signed URL pasted from a console. ADR-0008 does not exempt text merely because a person typed it. |
| Item 3: proposal rendering | As specified. The bundle format is a new versioned schema, `schemas/gate-proposal.v1.json` | The frozen `experiment-proposal.v1.json` describes ONE experiment; a gate-1 decision is over a SET, and `approvedItemIds` needs a bundle to refer into. |
| Validation "all seven checks" then "additional checks 8 and 9" | Implemented as nine ordered checks in one function | The document's own numbering reaches nine; the split was presentational. Order is part of the contract and is asserted. |
| Item 2: destructive classifier used at approval | The classifier is INJECTED into `@investigator/approvals` rather than imported | Keeps the approvals package independent of the executor, so approving cannot transitively reach a browser. Asserted by `tests/docs/approval-authority.spec.ts`. |
| `--scaffold` pre-fills `safetyAcknowledgements` | Scaffolds them as a COMMENTED template | `approval-record.v1.json` pins `acknowledged` to the constant `true`, so a provisional acknowledgement cannot exist. Writing the entry is therefore a deliberate act, which is the intent. |

## Defects this milestone found in frozen M0 artifacts

| Artifact | Defect | Fix |
| --- | --- | --- |
| `schemas/approval-record.v1.json` | `minItems` without a `type` in three conditional blocks, so the schema failed to COMPILE under Ajv strict mode. Nothing had ever validated against it | Added the explicit `array` type. No semantic change; `minItems` only ever applied to arrays |
| `apps/cli/src/commands/doctor.ts` | `--verify-lineage` checked only the predecessor link, so it would not have detected a record edited in place — the likeliest local tamper | Uses `verifyChain`, which separately detects a deleted record, an inserted or reordered one, and an in-place edit |

## Risks

| Risk | Mitigation |
| --- | --- |
| R10 rubber-stamping | Proposals render hypothesis, varied factor, and falsifier; approval requires explicit item IDs; destructive actions require justification text |
| Checksum canonicalisation bugs | Canonical form frozen (sorted keys, 2-space, LF, UTF-8 no BOM, trailing newline) and asserted by a round-trip test |
| Edit surface too narrow to be useful | Surface defined per gate in the ADR; widening requires an ADR, so the decision stays visible |
| R21 local tamper | Hash chain gives detection, not prevention; stated as residual risk |
| Approval UX friction pushes users to bypass | `--scaffold` produces a schema-valid pre-filled file; the CLI prints the exact next command at every step |
