# M4 — `classify_runs`, `analyze_pass_fail`, Eval Gates

## Governing principle

Playwright produces evidence. Deterministic software normalizes and measures evidence. DeepSeek interprets and prioritizes evidence. Humans authorize consequential transitions.

## Entry criteria

- M3 exit criteria met; M1–M3 gates green.
- Explicit `proceed`.

## Scope

1. Deterministic failure-signature computation: candidate signature generation from fingerprints, the machine-checkable predicate grammar, and signature-to-run matching.
2. Deterministic comparison engine: `compare_run_timelines` pre-computed group comparisons across the bounded feature set, with `comparisonId` assignment and emulation-mismatch refusal.
3. Tools: `get_run_summary`, `get_action_timeline`, `get_console_events`, `get_exception_events`, `get_failure_signature`, `compare_run_timelines`, `get_request`, `get_response_excerpt`, `get_dom_diff`, `get_storage_diff`.
4. Flow artifacts `/ai/flows/classify_runs/` and `/ai/flows/analyze_pass_fail/`, both partial-capable with `unitField`.
5. Finding persistence with the full level ladder, deterministic promotion requirements, automatic demotion with warnings, and the `confirmed_root_cause` hard fail.
6. `investigate classify` wired end to end, producing `RunClassification[]`, clusters, and the gate-2 proposal.
7. Gate-2 approval consumption: `ApprovedFailureSignature`, cluster edits, predicate tightening within the grammar.
8. Eval datasets and gates for both flows, including the eight named negative cases.

## Out of scope

Frequency statistics (M5) — M4 findings that need a rate are capped below `probable_trigger` until M5 exists. Minimization (M6). Report generation (M7).

Note: this ordering is deliberate. `analyze_pass_fail` can produce `observed` and `correlated`
findings without statistics, and the promotion requirement for `probable_trigger` mechanically
prevents it from over-claiming before M5 lands.

## Interfaces touched

Tool contract (ten tools), `MetadataStore` (findings, signatures, classifications, comparisons), approvals (gate 2), lineage (`classified_as`, `derived_finding`, `supported_by`, `approved_signature`).

## Exit criteria

1. Replay-mode eval passes every M4 gate, including all four hard-fail rows at zero.
2. Signature candidates are computed deterministically and identically across two runs of the extractor on the same evidence.
3. A classification contradicting the deterministic `RunOutcome` is rejected, not warned.
4. Demotion works: a finding whose evidence supports only a lower level is persisted at the lower level with a recorded warning; only `confirmed_root_cause` hard-fails.
5. A finding depending on a cited category that is `partial`, `redacted`, `unsupported`, `disabled`, or `corrupted` for any cited run is capped at `correlated`.
6. `probable_trigger` and above require at least one `field`/`expectedValue` citation; absence is rejected.
7. `confirmed_root_cause` is unreachable: no approval type exists to satisfy it, and the attempt yields `AI_CLAIM_UNSUPPORTED` with nothing persisted.
8. `compare_run_timelines` refuses comparisons across differing resolved emulation unless emulation is the declared varied factor.
9. Partial results persist only individually validated units, and the CLI exits 5 reporting completed/total.
10. Gate 2 permits predicate and cluster edits but rejects any attempt to alter a `RunOutcome` or a fingerprint.
11. All prior gates still pass.

## Acceptance tests

| ID | Test |
| --- | --- |
| M4-AT-1 | Deterministic signature computation reproducible byte-identically |
| M4-AT-2 | Predicate grammar: every legal predicate evaluates; an illegal one is rejected at parse |
| M4-AT-3 | Fabricated event ID in a finding -> `AI_REFERENCE_MISMATCH`, nothing persisted |
| M4-AT-4 | Wrong `expectedValue` on a real field -> `AI_REFERENCE_MISMATCH` |
| M4-AT-5 | `confirmed_root_cause` justified only by a passing control -> `AI_CLAIM_UNSUPPORTED` |
| M4-AT-6 | Finding citing a `partial` `responseBodies` category capped at `correlated` |
| M4-AT-7 | Emulation-mismatched comparison refused |
| M4-AT-8 | Classification contradicting `RunOutcome` rejected |
| M4-AT-9 | Partial result: budget exhausted mid-iteration; validated units persisted, unvalidated discarded, exit 5, counts reported |
| M4-AT-10 | Gate 2 edit attempting to change a run outcome rejected |
| M4-AT-11 | Tool contract test applied to all ten tools |
| M4-AT-12 | `get_response_excerpt` refuses with `TOOL_EVIDENCE_UNAVAILABLE` when the category is missing/disabled/unsupported, and marks partial explicitly when partial |
| M4-AT-13 | `confidence > 0.95` on a `correlated` finding rejected as internally inconsistent |
| M4-AT-14 | Non-empty `contradictingEvidence` at `high_confidence_trigger`+ without `contradictionResolution` -> demotion |

## Eval gates

All M4 gates in `docs/evaluation/eval-gates.md`. Datasets: `classify_runs` 10 positive (>= 20 runs each) / 5 negative; `analyze_pass_fail` 12 positive (>= 1 injected known difference each) / 8 negative including `root-cause-from-control.json`.

## Demo command

```bash
pnpm eval -- --flow classify_runs --mode replay
pnpm eval -- --flow analyze_pass_fail --mode replay
investigate run --workspace ./demo-ws --repeat 60
investigate classify --workspace ./demo-ws
cat ./demo-ws/investigations/INV-001/manifests/gate-2.target_failure.proposal.md
investigate approve target_failure --workspace ./demo-ws --scaffold
investigate approve target_failure --workspace ./demo-ws --from <file> --checksum <sha256>
investigate show --workspace ./demo-ws findings
```

## Risks

| Risk | Mitigation |
| --- | --- |
| R1 confident causal story from coincidence | Level ladder promotion requirements; `probable_trigger` needs statistics that do not exist until M5; falsifiers recorded from M3 |
| R2 fabricated references | Seven-check validation with exact field match; negative eval fixtures |
| R6 coarse signature matching two mechanisms | Predicate tightening at gate 2 is a human decision; signature granularity reported |
| R22 unbounded tool output | Pre-computed bounded comparisons instead of free-form queries; `maxEvidenceBytes` |
| Over-leveling | Automatic demotion with warnings; over-leveling scored separately in eval and gated at zero |
