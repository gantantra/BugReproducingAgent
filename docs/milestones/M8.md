# M8 — Hardening, Redaction Policy, Retention, Eval Suite Expansion

## Governing principle

Playwright produces evidence. Deterministic software normalizes and measures evidence. DeepSeek interprets and prioritizes evidence. Humans authorize consequential transitions.

## Entry criteria

- M7 exit criteria met; M1–M7 gates green.
- Explicit `proceed`.

## Scope

1. Redaction policy hardening: the full default policy from `docs/security/redaction-policy.md` implemented rule-by-rule, `hash-value` and shape descriptors, regex linear-time linting at policy load, per-field length caps, and policy fuzzing.
2. Trace redaction pipeline (`redacted-pipeline` disposition), if Q11 is answered in its favour; otherwise `withhold` remains the default and this item is dropped with the decision recorded.
3. Retention implementation: `retention apply` with tombstones, reproducer preservation, referenced-artifact preservation, and refusal without `--confirm`.
4. Adversarial eval expansion: prompt-injection cases embedded in fixture page content for every evidence-reading flow.
5. Dataset expansion to >= 20 positive and >= 10 negative cases per flow.
6. Cross-flow end-to-end eval: intake through report on fixtures with known injected mechanisms.
7. Operational hardening: `investigate doctor` completeness, startup safety checks (`NODE_OPTIONS`, `DEBUG=pw:*`), workspace permissions, orphan temp sweep, and disk-headroom pre-flight.
8. Windows ACL hardening for the workspace, if Q14 is answered in its favour.
9. Full re-run of every prior gate.

## Out of scope

New AI flows. New gates. PostgreSQL, S3, Redis, distributed workers, RBAC, a web UI, Jira writes. These remain designed-not-implemented.

## Interfaces touched

Redaction policy loader and enforcement across `evidence`, `ai-gateway`, and `reporting`; `ArtifactStore` (retention deletion and tombstones); CLI (`retention apply`, `doctor`).

## Exit criteria

1. Every rule in the default policy has positive and negative unit tests.
2. Policy fuzzing reports zero residue on generated secret payloads across encodings and nestings, and every regex respects the configured time bound.
3. Redaction is byte-identical across Linux and Windows for the same input and policy.
4. Adversarial eval: >= 3 prompt-injection cases per evidence-reading flow, and none alters the persisted output. An injection that induces a fabricated citation must be blocked by reference validation, and the test asserts the typed rejection rather than merely a benign outcome.
5. Datasets meet the expanded minimums, and all gates still pass at or above baseline.
6. Cross-flow end-to-end eval: >= 3 cases producing a report whose findings match the known injected mechanism at `correlated` or above with zero over-leveling.
7. Retention correctness: eligible artifacts deleted, tombstones written, reproducers and report-referenced artifacts preserved, manifests/lineage/approvals/ledger untouched, and a subsequent report render handles tombstoned citations honestly.
8. Startup safety checks behave as specified, including the `--allow-unsafe-debug` marking of the session and its manifests.
9. Every gate from M1 through M7 passes in the same CI run.
10. Known limitations documented and current: the five residual risks in the security model, the emulation boundary, the MVP unreachability of `confirmed_root_cause`, and any threshold renegotiations recorded in `docs/FREEZE-M0.md`.

## Eval gates

All M8 gates in `docs/evaluation/eval-gates.md`, plus every prior milestone gate re-run.

## Demo command

```bash
pnpm test                      # all unit + integration
pnpm test:reliability          # M1 gate, twice
pnpm eval -- --all --mode replay
pnpm eval -- --adversarial
investigate retention apply --workspace ./demo-ws --confirm
investigate doctor --workspace ./demo-ws --verify-lineage
```

Expected: every suite green, adversarial cases all blocked with typed rejections, retention applied correctly, lineage chain verified.

## Risks

| Risk | Mitigation |
| --- | --- |
| R23 redaction residue | Fuzzing, strict-mode default, verification passes at transmission and export, per-rule tests |
| R27 prompt injection | Structured-fact-only evidence path, reference validation, allowlists, budgets; adversarial cases gated |
| Trace pipeline complexity | Scoped by Q11; `withhold` is the safe default and drops the item entirely if chosen |
| Retention deleting evidence a report needs | Referenced-artifact preservation plus tombstones plus honest render |
| Gate suite runtime growth | Reliability gate cached separately; eval replay is deterministic and parallelisable; live mode stays nightly |
| Declaring "hardened" without evidence | Exit criterion 9 requires every gate green in one CI run, and known limitations must be documented, not omitted |
