# M0 — Architecture, Contracts, Schemas, Specs

## Governing principle

Playwright produces evidence. Deterministic software normalizes and measures evidence. DeepSeek interprets and prioritizes evidence. Humans authorize consequential transitions.

## Entry criteria

- Mission, non-negotiable principles, standalone MVP decision, tech stack, and frozen decisions supplied.

## Scope

Documentation, ADRs, versioned schemas, contracts, milestone specs, and acceptance-test specifications. No production code, no repository scaffold.

Deliverables:

- `CLAUDE.md`
- `docs/architecture/*` (overview, components, cli-contract, config-schema, llm-provider-contract, deepseek-adapter, queue-model, error-taxonomy, evidence-normalization-plane, capture-completeness, evidence-reference-model, ai-flow-artifacts, tool-allowlists, approval-state-machine, lineage-model, chrome-mobile-emulation, test-data-and-side-effects, reliability-strategy, build-vs-buy, risks, end-to-end-example, acceptance-criteria, open-questions)
- `docs/security/*` (security-model, redaction-policy)
- `docs/evaluation/*` (eval-harness, eval-gates)
- one milestone document per milestone under `docs/milestones/`, M0 through M8
- `docs/acceptance-tests/`
- twenty ADRs under `docs/adrs/`, ADR-0001 through ADR-0020, plus `docs/adrs/README.md`
- `schemas/*.v1.json`
- `docs/FREEZE-M0.md`

## Out of scope

Repository scaffold, `package.json`, TypeScript config, any implementation, any provider call, `/ai/flows/*` prompt content (structure specified, prose authored in M3+).

## Interfaces touched

All interfaces are *defined* here as specifications: `MetadataStore`, `ArtifactStore`, `WorkQueue`, `SecretStore`, `LlmProvider`, tool contract, flow artifact contract. None implemented.

## Exit criteria

1. Every document listed in Scope exists and is internally consistent.
2. The governing principle appears verbatim in `CLAUDE.md`, `docs/architecture/overview.md`, and every ADR touching execution, evidence, or AI.
3. All schemas listed in the brief exist, are versioned, and validate as JSON Schema.
4. Every milestone M0–M8 has entry criteria, exit criteria, scope, out of scope, interfaces touched, acceptance tests, eval gates where AI is involved, a demo command, and risks.
5. The ten M1 reliability-gate tests are specified with a fixture, a fixture test, and a pass criterion each.
6. Open questions are enumerated with recommendations and blocking status.
7. `docs/FREEZE-M0.md` exists and records deviations and resolved inconsistencies.

## Acceptance tests

Documentation-level, verified by inspection and by the M1 CI checks that begin enforcing them:

| ID | Check | Enforced from |
| --- | --- | --- |
| M0-AT-1 | Governing principle present verbatim in the required files | M1 CI script |
| M0-AT-2 | Every `schemas/*.json` parses and is a valid JSON Schema draft | M1 CI script |
| M0-AT-3 | Every schema has `schemaVersion` and `additionalProperties: false` at object levels | M1 CI script |
| M0-AT-4 | Every doc cross-reference resolves to an existing file | M1 CI script |
| M0-AT-5 | Frozen decisions 1–6 each traceable to a specific document section | Inspection |

## Eval gates

None. No AI flows execute in M0.

## Demo command

```bash
ls docs/architecture docs/adrs docs/security docs/evaluation docs/milestones docs/acceptance-tests schemas
```

Plus reading `docs/FREEZE-M0.md` and `docs/architecture/open-questions.md`.

## Risks

| Risk | Mitigation |
| --- | --- |
| Documentation drifts from implementation | M0-AT checks move into CI in M1; `flowHash` and schema emission validated in CI |
| Over-specification slows M1 | Schemas are `v1` and versioned; deviations are recorded as ADRs rather than blocking |
| Open questions block Phase B | Recommendations recorded for each; only Q3 (CI) and Q5 (model IDs) genuinely constrain claims |
