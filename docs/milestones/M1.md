# M1 — Standalone Foundation, Playwright Execution, Evidence Capture, Reliability Gate

## Governing principle

Playwright produces evidence. Deterministic software normalizes and measures evidence. DeepSeek interprets and prioritizes evidence. Humans authorize consequential transitions.

## Entry criteria

- M0 exit criteria met and `docs/FREEZE-M0.md` reviewed.
- Explicit `proceed` from the user.
- Node >= 20 and a package manager available (see open question Q1).

## Scope

1. Monorepo scaffold: pnpm workspace, Turborepo, all packages from the skeleton, `apps/cli` with `--help`, TypeScript config, ESLint (including the custom import-boundary rule), Prettier, Vitest, `.gitignore` excluding `.investigator/`, `node_modules/`, `dist/`, and `CLAUDE.md`.
2. Config loader: `config.yaml` + `env:` resolution + env overrides + strict validation + cross-field assertions.
3. SQLite `MetadataStore` adapter: WAL, single writer, `busy_timeout`, `BEGIN IMMEDIATE`, numbered migrations, append-only triggers, `CHECK` constraints for the job/outcome matrix.
4. Local filesystem `ArtifactStore` with SHA-256 integrity hashes and required `RedactionStamp`.
5. SQLite-backed durable `WorkQueue` with `JobState` / `JobTerminalReason` / `RunOutcome` separation, leases, heartbeat, and `reapStale`.
6. `SecretStore` env adapter with the branded `Secret` type (present, unused for execution).
7. One Playwright worker with bounded concurrency and the deterministic action interpreter over the closed action vocabulary.
8. Immutable run manifest writer: open, incremental artifact refs, seal, seal-hash verification.
9. Evidence collector: actions, navigation, console, exceptions, network metadata, DOM snapshots, screenshots, video, trace.
10. Redaction layer applied before persistence, with collection-time rules and the fail-closed persistence boundary.
11. `CaptureStatus` recorded per category per run, with reason codes and generated `limitations`.
12. Evidence Normalization Plane stages 1–5 sufficient for the gate: parse, normalize, redact, extract the listed features, build the timeline and index.
13. Five fixture apps.
14. All ten reliability tests implemented and passing.

CLI surface in M1: `investigate init`, `investigate run` (against a fixture experiment supplied as a local file, no gate enforcement yet is **not** acceptable — see Out of scope note), `investigate doctor`.

## Out of scope

- AI flows, any DeepSeek call, `ai-gateway` implementation beyond the unused adapter skeleton behind the interface.
- Approval gates (M2). Consequence: M1 `investigate run` accepts a **fixture experiment file** rather than an approved proposal, and this path is test-only, gated behind a `--fixture-experiment` flag that M2 removes. It is not a bypass of gate 1, because gate 1 does not exist yet; M2 adds enforcement and deletes the flag.
- Lineage beyond run manifests (M2).
- `intake`, `plan`, `classify`, `suite generate`, `frequency run`, `minimize`, `revalidate`, `report`, `export`.
- Frequency statistics (M5). The gate's `no_retry_hides_product_failure` test asserts the counting rule on raw counts, not on the M5 statistics module.
- Trace redaction pipeline (see open question Q11; M1 default is `withhold` unless directed otherwise).

## Interfaces touched

`MetadataStore`, `ArtifactStore`, `WorkQueue`, `SecretStore` (all implemented for MVP adapters); the run manifest and evidence event schemas; the tool contract is **not** implemented.

## Exit criteria

1. `pnpm install && pnpm build && pnpm test` succeeds from a clean checkout.
2. `investigate --help` lists the full frozen command set, with unimplemented commands exiting `1` with "not implemented in M1" rather than silently doing nothing.
3. `investigate init` creates a valid workspace; re-running is idempotent and never overwrites `config.yaml`.
4. All ten reliability tests pass, twice in the same CI job for the nine non-performance tests, on Linux and Windows.
5. The performance fixture completes 100 sequential runs with 100/100 `VALID_COMPLETED`, total wall clock < 600s, p95 per-run < 8s, disk growth < 1.5 GB, and no required category worse than `complete`.
6. Import-graph test proves `execution`, `evidence`, and `test-fixtures` do not reach `ai-gateway`, `ai-flows`, or any provider SDK.
7. A store call without a `RedactionStamp` raises `REDACTION_NOT_APPLIED`, asserted by test.
8. Every run manifest is schema-valid, sealed, immutable on second write, and contains resolved emulation values read back from the browser plus the seed and version stamps.
9. The extractor independently recomputes every `RunOutcome` and agrees with the executor on all fixture runs.
10. Coverage: the reliability gate plus unit tests cover every `RunOutcome` decision rule and every `CaptureStatus` reason code with at least one test.

## Acceptance tests

`docs/acceptance-tests/M1-reliability-gate.md` specifies all ten in full. Additional M1 acceptance tests:

| ID | Test |
| --- | --- |
| M1-AT-1 | Config loader rejects unknown keys, unresolvable `env:`, `redactLogs: false`, non-WAL journal mode, `heartbeatMs >= leaseMs/3`, and a target origin absent from `allowedOrigins` |
| M1-AT-2 | Job/outcome `CHECK` constraints reject every illegal combination in the matrix |
| M1-AT-3 | Append-only triggers reject update and delete on lineage, approvals, AI ledger, and manifest tables |
| M1-AT-4 | Claim under simulated contention never double-claims a job |
| M1-AT-5 | `Secret` returns `[redacted]` under interpolation, `JSON.stringify`, `util.inspect`, and error serialisation |
| M1-AT-6 | `EXEC_ORIGIN_NOT_ALLOWED` aborts a run navigating outside the allowlist and classifies it `AUTOMATION_FAILED` |
| M1-AT-7 | `production` classification and a matching `productionOriginPatterns` origin are both rejected |
| M1-AT-8 | Redaction is byte-identical across Linux and Windows for the same input and policy |
| M1-AT-9 | `investigate doctor` prints no secret material and reports breaker/queue/integrity state |
| M1-AT-10 | Startup warns when `NODE_OPTIONS` contains a diagnostic-report or heap-snapshot flag, and refuses `DEBUG=pw:*` without `--allow-unsafe-debug` |

## Eval gates

None. No AI flows in M1.

## Demo command

```bash
pnpm install && pnpm build
investigate init --workspace ./demo-ws
investigate run --workspace ./demo-ws --fixture-experiment packages/test-fixtures/experiments/product-failing-intermittent.json --repeat 20
investigate doctor --workspace ./demo-ws
pnpm test:reliability
```

Expected: 20 runs, a seed-predicted subset `PRODUCT_FAILED`, the rest `VALID_COMPLETED`, one sealed manifest each, complete evidence for required categories, and all ten reliability tests green.

## Risks

| Risk | Mitigation |
| --- | --- |
| R13 normalization non-determinism | Injected `Clock`, seeded `Rng`, pure plane, byte-identical rebuild test on both OSes |
| R12 disk exhaustion | Disk-growth assertion in the performance test; `video: on-failure` default |
| R19 Windows/Linux divergence | Gate runs on both; process-kill semantics tested explicitly |
| R20 SQLite driver instability | Probe both drivers first, record the choice as ADR-0021 |
| R3 automation vs infrastructure misclassification | Rule order, `INCONCLUSIVE` for ambiguity, `fixture_app_classification` gate |
| Trace redaction cost | Default `withhold` in M1; pipeline deferred to M8 pending Q11 |
| Performance budget unmet on the actual runner | Budget renegotiated in writing in `docs/FREEZE-M0.md`, never silently relaxed |
