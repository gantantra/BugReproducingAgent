# M6 — `suggest_minimization`, Revalidation, Controls

## Governing principle

Playwright produces evidence. Deterministic software normalizes and measures evidence. DeepSeek interprets and prioritizes evidence. Humans authorize consequential transitions.

## Entry criteria

- M5 exit criteria met; M1–M5 gates green.
- Explicit `proceed`.

## Scope

1. Tools: `get_sequence`, `get_previous_minimization_results` (`get_failure_signature` already exists from M4).
2. Flow artifact `/ai/flows/suggest_minimization/`, not partial-capable.
3. Schema enforcement that every candidate is a strict subsequence of the current sequence or a declared substitution from the closed set. No new actions may be introduced.
4. `investigate minimize`: multi-round loop — propose candidates (AI), execute each deterministically at `--repeat-per-candidate`, measure the retained reproduction rate against the **approved signature predicate**, and rank verdicts `retained` / `lost` / `inconclusive`.
5. Passing-control generation: deterministic construction of a control variant differing only in the asserted factor, executed at the same repetition count.
6. `investigate revalidate`: re-execute the current candidate and its control, re-verify artifact integrity and manifest seals, recompute completeness, and produce a `ValidatedReproduction`.
7. `high_confidence_trigger` promotion: now satisfiable via a matched control set with disjoint intervals.
8. Gate-3 proposal rendering, including the explicit warning path when no candidate meets the retention threshold.
9. Eval datasets and gates for `suggest_minimization`.

## Out of scope

Reproducer packaging and report generation (M7). Any change to `analyze_pass_fail` beyond consuming the new promotion evidence.

## Interfaces touched

Tool contract (two new tools), `MetadataStore` (minimization candidates, validated reproductions, controls), `WorkQueue` (candidate batches), approvals (gate 3), lineage (`proposed_reduction`, `validated_as`, `controlled_by`, `approved_reproduction`).

## Exit criteria

1. Replay-mode eval passes every M6 gate, with the two hard rows at zero: non-subsequence candidates and accepted candidates that lose the approved signature.
2. Retention is measured against the **approved signature predicate**, not merely "the run failed". A candidate that fails for a different reason is `lost`, not `retained`.
3. Every candidate execution is deterministic, seeded, and produces full manifests and evidence like any other run.
4. A passing control is generated for the accepted candidate and executed at the configured repetition count, with a Wilson interval.
5. When no candidate meets the retention threshold, `investigate minimize` says so explicitly and proposes gate 3 with the best available candidate plus a recorded warning. It never silently accepts a candidate below threshold and never reports the threshold as met.
6. `high_confidence_trigger` promotion requires a matched control with disjoint intervals; otherwise the finding stays at `probable_trigger`.
7. `confirmed_trigger` requires an approved gate-3 reproduction **and** a passing control, both revalidated at the configured repetition count.
8. `investigate revalidate` re-verifies every artifact hash and manifest seal and fails with exit 9 on any mismatch.
9. Gate 3 permits removal and reorder within the sequence but rejects adding an action absent from the pre-minimization sequence and rejects changing the approved signature.
10. All prior gates still pass.

## Acceptance tests

| ID | Test |
| --- | --- |
| M6-AT-1 | Candidate that adds an action -> schema rejection |
| M6-AT-2 | Candidate that is not a subsequence and not a declared substitution -> schema rejection |
| M6-AT-3 | Fixture with a known minimal reproducing subsequence: the loop converges to it |
| M6-AT-4 | Candidate that fails via a different signature is classified `lost`, not `retained` |
| M6-AT-5 | No candidate meets the threshold: explicit report, gate-3 proposal carries the warning, exit code reflects success with warnings rather than a false pass |
| M6-AT-6 | Control generation differs only in the asserted factor; the diff between reproduction and control sequences is asserted to be exactly that factor |
| M6-AT-7 | `high_confidence_trigger` blocked without a matched control; permitted with one |
| M6-AT-8 | `confirmed_trigger` blocked without an approved gate-3 reproduction |
| M6-AT-9 | `revalidate` detects a corrupted artifact byte and exits 9 |
| M6-AT-10 | `revalidate` detects a tampered manifest seal and exits 9 |
| M6-AT-11 | Gate 3 edit adding a new action rejected |
| M6-AT-12 | Tool contract test applied to the two new tools |
| M6-AT-13 | Minimization respects `safety.maxRunsPerInvestigation` and reports truncation rather than exceeding it |

## Eval gates

All M6 gates in `docs/evaluation/eval-gates.md`. Dataset: 8 positive cases with known minimal subsequences, 5 negative including new-action, non-subsequence, and no-reduction-possible cases.

Retention-threshold semantics follow open question Q13; the recommended reading is that the hard gate is "the reduced case still reproduces with a lower interval bound above 0", with retention-versus-original reported as a quality metric.

## Demo command

```bash
investigate minimize --workspace ./demo-ws --max-rounds 3 --repeat-per-candidate 40
investigate revalidate --workspace ./demo-ws --repeat 60 --include-control
cat ./demo-ws/investigations/INV-001/manifests/gate-3.final_reproduction.proposal.md
investigate approve final_reproduction --workspace ./demo-ws --scaffold
investigate approve final_reproduction --workspace ./demo-ws --from <file> --checksum <sha256>
investigate show --workspace ./demo-ws findings
```

Expected: candidate table with retained rates and intervals, a passing control at 0 failures with a disjoint interval, and a finding promoted to `high_confidence_trigger` or `confirmed_trigger`.

## Risks

| Risk | Mitigation |
| --- | --- |
| R6 minimized case fails for a different reason | Retention measured against the approved predicate; `lost` verdict for signature change |
| Timing-sensitive repros lose rate under reduction | Reported honestly; threshold semantics per Q13; the operator decides at gate 3 |
| Minimization run cost | `--max-rounds`, `--repeat-per-candidate`, investigation run ceiling, reported truncation |
| Control that differs in more than the asserted factor | Sequence diff asserted to be exactly the factor (M6-AT-6) |
| Over-promotion to `confirmed_trigger` | Requires both an approved gate-3 reproduction and a revalidated passing control |
