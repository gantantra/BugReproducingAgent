# Components and Interfaces

Status: M0 frozen candidate

## Governing principle

Playwright produces evidence. Deterministic software normalizes and measures evidence. DeepSeek interprets and prioritizes evidence. Humans authorize consequential transitions.

## 1. Storage seam interfaces

These four interfaces are the entire portability story. They are authored in `packages/storage`
and are the only place adapters exist.

### 1.1 MetadataStore

```ts
export interface MetadataStore {
  migrate(): Promise<void>;
  // All writes go through a short transaction. No long-lived transactions.
  tx<T>(fn: (t: MetadataTx) => Promise<T>): Promise<T>;
  read<T>(fn: (t: MetadataReadTx) => Promise<T>): Promise<T>;
  close(): Promise<void>;
}

export interface MetadataTx extends MetadataReadTx {
  insertInvestigation(rec: InvestigationRecord): Promise<void>;
  insertRun(rec: RunRecord): Promise<void>;
  insertLineageEdge(rec: LineageRecord): Promise<void>;
  insertApproval(rec: ApprovalRecord): Promise<void>;
  insertAiCall(rec: AiCallRecord): Promise<void>;
  insertArtifactRef(rec: ArtifactRefRecord): Promise<void>;
  // No update/delete for lineage, approvals, ai_calls, run manifests.
}
```

Rules:

- IDs are generated by the application (`core/ids`), never by the database. No
  `last_insert_rowid()` in any interface signature or return value.
- Ordering is by explicit monotonic sequence columns, never implicit rowid order.
- Lineage, approvals, AI call ledger, and run manifest rows are append-only. Enforced by SQLite
  triggers in M1 and by the absence of update/delete methods in the interface.

### 1.2 ArtifactStore

```ts
export interface ArtifactStore {
  put(req: {
    investigationId: InvestigationId;
    runId?: RunId;
    kind: ArtifactKind;
    filename: string;
    bytes: Uint8Array | NodeJS.ReadableStream;
    contentType: string;
    redactionApplied: RedactionStamp;   // required, not optional
  }): Promise<ArtifactRef>;             // includes sha256, byteLength, storedAt

  get(ref: ArtifactRef): Promise<NodeJS.ReadableStream>;
  head(ref: ArtifactRef): Promise<ArtifactRef>;
  verify(ref: ArtifactRef): Promise<{ ok: boolean; observedSha256: string }>;
  list(investigationId: InvestigationId, filter?: ArtifactFilter): Promise<ArtifactRef[]>;
}
```

Rules:

- `put` is content-hashed at write time. `ArtifactRef.sha256` is computed by the store, never
  supplied by the caller.
- `redactionApplied` is a required field. There is no code path that stores an artifact without
  declaring which redaction policy version was applied and what it did.
- Artifacts are immutable. There is no `update`. Deletion happens only via the retention command.

### 1.3 WorkQueue

```ts
export interface WorkQueue {
  enqueue(job: NewJob): Promise<JobId>;
  claim(workerId: WorkerId, leaseMs: number): Promise<ClaimedJob | null>;
  heartbeat(jobId: JobId, workerId: WorkerId): Promise<void>;
  finish(jobId: JobId, terminal: { reason: JobTerminalReason; runOutcome: RunOutcome }): Promise<void>;
  reapStale(now: Timestamp): Promise<ReapResult>;   // stale CLAIMED/RUNNING -> TERMINAL/INTERRUPTED
  stats(investigationId: InvestigationId): Promise<QueueStats>;
}
```

See `docs/architecture/queue-model.md` for the state machine and the reap semantics.

### 1.4 SecretStore

```ts
export interface SecretStore {
  // Returns an opaque handle, not the value, wherever the caller does not need the value.
  has(name: SecretName): Promise<boolean>;
  // The only method that yields the value. Callers must not log, store, or serialise the result.
  reveal(name: SecretName): Promise<Secret>;   // Secret has a toString() that returns "[redacted]"
}
```

Rules:

- `Secret` is a branded wrapper whose `toString`, `toJSON`, and `util.inspect.custom` all return
  `"[redacted]"`. A unit test asserts this for template interpolation, `JSON.stringify`, and
  `console.log`.
- MVP adapter reads `process.env` only. `DEEPSEEK_API_KEY` is the only secret in M0 scope.

## 2. core

- `ids`: typed, prefixed, sortable IDs. `INV-001`, `EXP-003`, `RUN-017`, `JOB-…`, `EV-…`,
  `FIND-…`, `TRACE-…`, `APPR-…`. Human-readable per-investigation counters for user-facing IDs;
  a ULID suffix internally where global uniqueness matters.
- `errors`: the typed error taxonomy (see `docs/architecture/error-taxonomy.md`).
- `clock`: `Clock` interface with `now(): Timestamp`. Execution and normalization receive an
  injected clock. A `FrozenClock` is used in tests.
- `rng`: seeded deterministic RNG. Every run manifest records the seed.
- `schema`: schema registry, version negotiation, strict validation, unknown-field rejection.

## 3. execution

Responsibilities:

1. Claim a job from `WorkQueue`.
2. Resolve the run context: browser channel, emulation parameters, seed, environment target.
3. Write the run manifest *before* the first browser action, then seal it after the run.
4. Drive Playwright through the approved action list using a deterministic interpreter.
5. Emit the raw event stream and raw artifacts.
6. Decide `RunOutcome`.
7. Call `finish` exactly once.

The action interpreter supports a closed set of action types (see `schemas/action.v1.json`). There
is no `eval`, no arbitrary script injection from AI output, and no action type that can be
introduced by a model without a schema change and a human-approved gate.

## 5. tools

Each tool is a function `(input) => Promise<ToolResult>` where the result is normalized, redacted,
schema-validated fact data. Tools are registered in a registry keyed by tool ID, and a flow may
only call tools present in its own `flow.yaml` allowlist. Attempting to call a non-allowlisted tool
is a typed `TOOL_NOT_ALLOWED` error that is charged against the flow budget and surfaced as a
warning on the flow result.

## 9. reporting

- Builds the `ReproducerPackage`: a self-contained directory with a static Playwright spec, the
  resolved emulation parameters, the fixture or environment target, the seed, and a README.
- Renders the `FinalReport` to Jira-ready markdown. Rendering is deterministic and mechanical: it
  refuses to render a report whose findings fail reference validation.

## 10. apps/cli

Thin. Parses arguments, loads config, resolves the workspace, dispatches to a use-case function in
a package, and formats output. No business logic. Exit codes are part of the contract; see
`docs/architecture/cli-contract.md`.
